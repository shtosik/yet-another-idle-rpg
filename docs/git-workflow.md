# Git workflow

Several agent sessions (Claude, Codex) often run in parallel on this repo, sharing the main checkout.

- **Keep the main checkout on its current branch.** `git checkout` / `git switch` there moves every other session onto your branch and mixes uncommitted work.
- **`origin/staging` is the default for everything**: new work, and also reading code or researching ideas. `main` is the released state, explored only for a hotfix or when asked; local `main` lags further behind. To read staging without a worktree, run `git fetch origin staging` first, since `git show origin/staging:<path>` reads the local remote-tracking ref, which is stale until fetched.
- **New work starts from `origin/staging`**. Create a worktree with `node scripts/worktree.mjs feat/<name>` (add `--from <ref>` for another base): it fetches, runs `git worktree add ../yari-<name> -b feat/<name> origin/staging` and `npm ci` inside it. Work only inside it. (`claude --worktree <name>` branches from the default branch, `main`, so it doesn't fit new work.)
- **One feature, one PR into `staging`**, with plan steps as commits on its branch, so fixes and reviews stay in one place. A hotfix branches from `origin/main` (`docs/deployment.md` → Releases).
- **PRs go back to where the branch came from**: feature PRs into `staging`. `main` takes only `release/*` and `hotfix/*` PRs, and CI fails on anything else.
- Right after `git worktree add`, switch the session into the worktree with the `EnterWorktree` tool (`path: ../yari-<name>`). The desktop app's diff pane only shows the session's own folder, so edits made in a worktree the session never entered don't show up there.
- **Don't remove worktrees by hand.** `scripts/worktree-prune.mjs` runs detached from the SessionStart hook (also after `/clear`) and removes `../yari-*` worktrees and their local branch once the branch is merged (merged PR with the same tip, or ancestor of `origin/staging`), the tree is clean and unlocked, and git state is untouched for 12 h. Unmerged, dirty or recent ones stay. `node scripts/worktree-prune.mjs --dry` lists what it would remove.
- A worktree needs its own `node_modules` (`scripts/worktree.mjs` installs it; otherwise run `npm ci` there). A junction or symlink to the main checkout's `node_modules` is unsafe: removing the worktree has deleted the real `node_modules` before.
- In a worktree session, run git as single plain commands (no `cd &&` chains or `$(…)` around git). The sandbox also refuses a command whose text names git anywhere it can't parse: a heredoc, a `node -e` script or a URL containing `git`. Write the script to a file and run `node <file>`. `gh` with `--jq` filters or inside loops is refused too: use `scripts/pr-comments.mjs` / `scripts/pr-status.mjs`, or one plain `gh` call per PR. Run `git show <ref>:<path>` in PowerShell; Git Bash rewrites the `:<path>` part into a Windows path.
- Dev server in a worktree: other worktrees may hold 4200 and stopped servers can keep their port on Windows, so run `npx ng serve --port 0` in the background and wait until its output contains `localhost:` (the `Local:` label has colour codes inside it, so grepping for `Local:` never matches); the port follows, after more colour codes.
- Stage only files you changed yourself; other sessions' uncommitted work may be in the tree.

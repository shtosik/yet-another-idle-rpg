# Quests

## Purpose
Multi-step story objectives handed out by NPCs. Quests are started, advanced and finished from dialogue; the quest panel on the right lists them.

## Key files
- `src/data/quests-data.ts:QUEST_DATA` — per quest: `startRequirements`, `steps[]` (each with `description`, `turnInNpc` and `requirements`), `rewards`.
- `src/enums/ids/quest-id.enum.ts:QuestID`.
- `src/app/store/quests/quests.store.ts:QuestsStore` — `questStepProgression` and `stepKillBaselines` (saved), `dialogueFlags`, `pinnedQuests` (saved), `togglePin`, `startQuest`/`advanceQuest`/`endQuest`, `handleQuestCompleted` (rewards + modal), `questEnemyKills`/`questWaveKills`, `requirementProgress` and `requirementRows` (current/target and the quest panel's lines for any requirement; the panel and `DialogueManagerService` both use them).
- `src/app/store/quests/requirement-handlers.ts` — `REQUIREMENT_HANDLERS`, one entry per `RequirementProps` type, so a new type fails to compile until handled: `progress`, the panel `rows` (label, zone link; a `reputation` one is points against the tier threshold, labelled "Mawood Honored"), `baseline` for kill requirements (`killBaseline`) and `consumed` for the items a turn-in takes (`consumedItems`, behind `getStepItems`).
- `src/app/services/quest-status.ts` — `getQuestStatus`, `canAdvanceQuest`, `isQuestAvailable`, `matchesQuestState`, `getStepItems`, `getActiveQuestIds`. Status is always derived from the saved step.
- `src/app/components/game/quests/quests.component.ts` — quest panel: the tab bar (arrow keys move between tabs); each tab is its own component: `quest-list/` (Quests) and `reputation/` (tier and progress per unlocked reputation town). The quest list shows active quests (ready ones first, tagged **Ready**) with progress for each requirement of the current step (a quest item reads "Find {item}"; a single requirement shows only Done once met), the step description on click, and completed quests behind a toggle. Links: "Talk to {NPC}" (the current step's `turnInNpc`, placed by `npcPlace` in `src/data/helpers/npc-places.ts`; shown once the step's requirements are met; needs the Map and the town unlocked) and a zone icon on unfinished kill requirements (`GameNavigationService.fightIn`; keeps the current wave when already in that zone). Pinned quests (`pinnedQuests`, saved, dropped on completion) sort first. Never shows a step number, step count or rewards, so quest length isn't spoiled.
- `src/app/components/modals/quest-completed/` — reward modal.

## Data flow
1. **Start**: a dialogue result with effect `{ type: 'quest', action: 'start' }` sets the step to 1. The dialogue engine hides a start result unless the quest is `available` (not started and `startRequirements` met); still gate the route to the offer node with `QuestState.available` so the player isn't shown an offer they can't take. `startQuest` itself is a no-op once the quest has started.
2. **Progress**: requirements (`item`, `stat`, `enemy` kill count, `wave` kill count, `quest`, `reputation` tier, `professionLevel`: the profession's expertise is at least `level`, 0 while locked, shown as '{Profession} expertise'; `pickedItems`: the items rolled for a repeatable order, see Repeatable orders) are checked, not tracked. When a quest reaches a step, the store snapshots the lifetime kill counters that step's `enemy`/`wave` requirements read (`stepKillBaselines`); those requirements count kills since then (`questEnemyKills`/`questWaveKills`).
3. **Advance**: a turn-in result gated by `QuestState.readyToAdvance` (with `step`) applies `action: 'advance'`, which `advanceQuest` ignores unless the step is still ready (items can be used up while the turn-in node is open). The store first takes the step's `item` requirements from the inventory, so turn-ins never restate them. Advancing past the last step completes the quest.
4. **Complete**: step becomes `QUEST_STEP_AFTER_COMPLETED` (9999), the step's items are taken, the kill baseline is dropped, and `handleQuestCompleted` grants `rewards` (stats, items town `reputation` through `ReputationService.gain`, see `towns-shops-guild.md`, and `professionXp` through `ProfessionService.gainXp`, which toasts a level-up; XP for a locked profession is dropped) and opens the modal, which lists reputation as "+20 La Harpar reputation" and profession XP as "+100 Farming XP". A reputation reward names its `reputationId`, so a quest can credit a town other than the giver's; `validate` allows only `REPUTATION_IDS`. `action: 'end'` completes from any step, but only while that step is ready (`isStepReady`, the same recheck as `advanceQuest`); `endQuest` itself skips the check. `advanceQuest`/`endQuest` are no-ops unless the quest is active and, when they complete it, its item rewards fit (see below). Cheat: `dev.completeQuest(questId)` starts and ends a quest, rewards included.
5. Enemy drops with `requiredActiveQuestId` only roll while that quest's current step requires the item and the player holds fewer than required. `getQuestDropLimits(progression, orders, itemCount)` snapshots the missing amounts from current-step requirements (an Order's picked items included) and inventory counts once per Kill resolution batch (one online kill or a whole offline claim); `rollKills` subtracts amounts already rolled in the batch (`remainingDropLimits`) and `rollDropList` caps each drop at the remainder. Nothing drops before or after the item step, once enough is held, or after completion, even if other step requirements are unmet.

Saved step encoding: `undefined` = not started, `1..n` = on step n, `9999` = completed.

## Intended behavior (owner decisions)
- **A Tale of a Captain is unfinished on purpose.** `captainsLetter` has no source and `rewards` is empty (no reputation either); it will be finished later.
- Completing a quest must be blocked when item rewards don't fit in the inventory (see `player-stats-inventory-equipment.md`).

## The Cold Forge
Phurgo at Lirold's Forge offers `QuestID.theColdForge` (20) as soon as the player can reach him; there is no extra quest or reputation gate. Its five steps are: talk to Ludo Crane at the Arena; deliver one Phurgo's Forge Tongs to Phurgo; talk to Marvin at La Harpar's Exploration Guild; deliver one existing Fish & Apple Pie to Phurgo; deliver ten Ancient Wood to Phurgo. The two talk steps have empty requirements and advance only at their named NPC. The store consumes the three deliveries once. Completion gives 2000 XP and 400 gold and gates Phurgo's Upgrade gear service, without a separate flag or demonstration merge.

Goblin Scavengers drop `ItemID.phurgosForgeTongs` (181), an unsellable, indestructible quest item, at 1 in 50 with `requiredActiveQuestId: QuestID.theColdForge`. The quest-drop cap (step 5 above) keeps it to one: it rolls only on the step that needs it, and stops once held.

## Farming Guild chain
Eight quests (`QuestID` 21-28), unlocked by Sylvie's `seedsFromTheTerrace` after `silkAndWater`. Its start result gives the Guild Letter, opens the farm Site (`unlockSite`) and teaches Farming (`unlockProfession`); this is the only way into the farm. Marta (`farmWarden`) ends the talk step when the letter is delivered. After it: `theFirstFurrow` (4 Turnip, Turnip Stew recipe) → `wheatForTheGuild` (10 Wheat, Farmer's Bread recipe) → `silverleafForSylvie` (Sylvie, 6 Silverleaf, Farming expertise 5, Silverleaf Tonic recipe) → `anOrchardAgain` (12 Apple, expertise 8, +1 plot) → `theGrowersTable` (5 Turnip Stew and 5 Harvest Pie, Farming Guild Honored, +1 plot, Skill Point Book). Rewards are XP, gold, Guild reputation and Farming XP; early steps also pay seeds, which go to the seed tally (`farming.md`). The two plot grants are read from these quests' completion by the plot count. `marthasOrder` (opens with `theFirstFurrow`; Turnip, Wheat from Friendly) and `wicksOrder` (opens with `wheatForTheGuild`; animal drops by Guild tier and unlocked Zone) are the repeatable orders below. Names are in `quests.json`; the dialogue is `dialogues/farmWarden`, `farmDrover` and the new Sylvie nodes (`dialogue.md`). Voices and backstory: `docs/character/farm/`.

## Repeatable orders
A quest with `repeat` (`RepeatProps`: `reputationId`, `professionId`, `picks`, `pool` of `OrderEntry`) can be started again after each completion. `marthasOrder` and `wicksOrder` (Farming Guild) use it, one pick per order from a pool in `quests-data.ts`; the specs use a test-only fixture. Rules (`orders.ts`, `QuestsStore`):
- **Start rolls and saves.** `startQuest` picks `picks` distinct pool entries whose `minTier` the town reputation meets and (when set) one of whose `sourceZones` is unlocked, rolls each amount 10-20, computes the base rewards (`reputation = ceil(amount / 10 × reputationPer10)`, `gold = amount × goldPerItem`, `farmingXp = round(amount × xpPerItem)`) and saves `orders[questId] = { requirements, rewards }`, then calls `saveGameStateNow`, so a reload never re-rolls. It does nothing while the order's cooldown runs or nothing is eligible.
- **The step requirement** `{ type: 'pickedItems' }` reads `orders[questId].requirements`: its handler's `progress` (items held, capped per pick, against the total), `consumed` (through `getStepItems(questId, step, orders)`: turn-in and reservations) and `rows` (one quest-list row per picked item).
- **One completion path.** `QuestsStore.completeOrder(questId, now)`: both `advanceQuest` and `endQuest` call it for a `repeat` quest. It is rejected, changing nothing, unless the order is active, the player holds the saved items and the order's `order:<QuestID>` cooldown (`turn-in-cooldown.ts`) is over. Otherwise it takes the items, pays the saved reputation, gold and profession XP (the order's Farming XP × (1 + the profession's `xpMultiplier` stat from `PROFESSIONS_DATA`, `farmXpMultiplier` for farming)), writes `lastTurnInAt`, bumps `questCompletions`, clears `orders[questId]` and the step (so the quest is `notStarted` again) and opens the reward modal. Order rewards contain no items.
- **Availability.** `DialogueManagerService` hides a start result while the order's cooldown runs; an order never blocks other turn-ins (each has its own key).
- **Reservations.** `DialogueManagerService.turnIn` counts the picked items of active orders as kept, so a reputation bundle can't consume them.
- `dev.completeQuest` on an order starts it and completes it only if the player already holds the picked items.

## Invariants & gotchas
- Steps are 1-based in saves and 0-based in `steps[]` (`steps[step - 1]`).
- Turn-in ordering in the NPC's tree matters: see the quest hub order in `dialogue.md`.
- `QuestState.active` means started; `readyToAdvance` means started and the current step's requirements are met.
- `QUEST_DATA` is the only place requirements live. Turn-ins don't add `requirementsNeeded` or `item` `take` effects for them.
- One-time quests have no cooldown. Reputation bundle turn-ins (not quests) do: `QuestsStore.lastTurnInAt` holds the last run per `TurnInKey` in Game time (`GameClock`, so a moved device clock skips no cooldown and time away counts up to the 24 h offline cap) and is saved, and repeatable orders share it (`dialogue.md`, "Condition (turn-in cooldown)").
- A start result only shows while its quest is `available`, so it can't share a result with the `end` that unlocks it. Put the follow-up `start` on the next node.
- Quests started in a save from before `stepKillBaselines` have no baseline and count lifetime kills.
- Quest step descriptions retain plain English fallbacks. The quest panel first resolves `quests:steps.<questKey>.<step>` (1-based); The Cold Forge provides all five translations (see `localization.md`).

## Known issues
- **A quest whose item rewards don't fit is refused, never paid partly.** Completion is an atomic Item grant: `advanceQuest` (last step) and `endQuest` check `canPayQuest` (the rewards fit once the step's items are taken) before taking anything, and `handleQuestCompleted` grants the items first and pays nothing else (stats, reputation, profession XP, modal) when the grant is refused. Dialogue greys the option out beforehand through the quest effect's `cost` (`DialogueManagerService.canApplyResult`, the same routing as `PlayerStore.canGrant`).

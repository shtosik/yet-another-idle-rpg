# Player stats, inventory and equipment

## Purpose
`PlayerStore` holds everything about the player character: stats, level and XP, gold, the inventory grid, equipped gear, and progress flags. Most other systems read from or write to it.

Toric's Forge Tongs (`ItemID.toricsForgeTongs`) use the existing quest item rules: unsellable (`value: -1`), indestructible and consumed by The Cold Forge's step 2. Their temporary icon is the existing letter image; see `quests.md` for their drop source and the quest-drop cap dependency.

## Key files
- `src/app/store/player/player.store.ts:PlayerStore` — state, the derived `stats`, `updatePlayerStats`, `addItems`/`removeItems`, `equipItem`/`unequipItem`, `useItem`, `processBattleEnd`, unlock flags.
- `src/app/store/player/stats.ts` — `deriveStats`, the modifier sources (`equipmentModifiers`, `skillNodeModifiers`, `buffModifiers`, `consumableModifiers`, `bonusModifiers`; zone mastery's `masteryModifiers` lives in `zone-mastery.ts`), `SourcedModifiers` and `statContributions` (per-source breakdown), `RESOURCE_STATS`, inverted stats.
- `src/app/components/game/player-stats/` — the stats panel: groups and rows from `stat-rows.ts:STAT_GROUPS`, each row's tooltip breaks the stat down by source.
- `src/app/store/player/player.ts:statsInitialState` — every stat's base value (and its unit, in comments).
- `docs/adr/0002-player-stats-derived-from-sources.md` — why stats are derived.
- `src/app/store/player/inventory.ts` — inventory tabs (`INVENTORY_TABS`, `tabOf`), tab capacity (`inventoryCapacity`, `slotDeltas`), the save migration split (`splitInventory`) and pure helpers over all tabs: `addItems`, `removeItems`, `canFit`, `missingSlots`, `missingSlotsByTab`, `blockedTab`, `countItem`, `maxAffordable`, `resizeInventory`.
- `src/app/store/player/merge.ts` — merge sources, pure eligibility preview (`evaluateMerge`), gold cost (`mergeCost`) and injectable chance roll (`rollMerge`).
- `src/types/player/player-stat.type.ts:PlayerStat` — the stat union, plus `multiplierStats`, `percentageStats`, `additivePercentStats` (display format, used by `stat-to-percentage.pipe.ts`).
- `src/interfaces/item.interface.ts:Item` — item union by `ItemType`.
- `src/enums/equipment-slot.enum.ts:EquipmentSlot` — 11 slots; `EquipmentSlotKey` is the string key used in `PlayerState.equipment`.
- `src/app/services/skill-tree.service.ts:SkillTreeService` — skill node buy/refund/respec (see `skill-tree.md`).

## Data flow
- **Stats** (`PlayerStore.stats()`) are a computed `Record<PlayerStat, number>`: `statsInitialState` + equipped gear + stat skill nodes × level + active buffs (`BattleStore.activeBuffs`) + active consumable effects (`BattleStore.consumableSlots`) + `permanentBonuses`, with saved **resources** on top. Nothing stores the total. `PlayerStore.sourcedModifiers()` keeps the modifiers grouped by source (gear, skills, buffs, food and potions, permanent bonuses, zone mastery); `stats` flattens it, and the stats panel's tooltip reads it through `statContributions`.
- **Title picker** (`player-stats/title-picker/`): above the stats sheet once a title is earned; a select with "None" and the earned titles (`PlayerStore.selectTitle`, see `towns-shops-guild.md`).
- **Stats panel** (main and Settings tabs, spanning both middle columns): Combat, Magic, Progress, Weakness damage and Damage vs enemy types. A row shows when marked `always` in `STAT_GROUPS` or when its value differs from `statsInitialState`; "Show all stats" lists every row. Level, XP and gold live in the HUD, not here. Hovering or focusing a row shows a one-line description (`app:statsPanel.descriptions.<stat>`, or the row's shared `description` key for weakness and enemy-type rows), Base, each source's flat and percent part, and Total; on inverted stats a positive data amount shows as a minus.
- **Resources** (`PlayerState.resources`: `experience`, `level`, `unspentSkillPoints`, `goldCoins`, `mana`) are earned and spent with `updatePlayerStats([{ stat, amount }])`. The same call with any other stat adds a **permanent bonus** (`PlayerState.permanentBonuses`): used reward items, quest stat rewards, dialogue stat effects. Gear, nodes, buffs and consumables never call it.
- **XP**: adding `experience` runs `handleExperience`, which levels up (possibly several times) and grants 1 skill point per level. Formula: `src/app/pipes/calculate-xp.pipe.ts`.
- **Inventory tabs** (`PlayerState.inventory: Record<InventoryTab, Inventory>`): Gear, Consumables, Materials, Pets, Quest. `tabOf(id)` picks the tab: `equipment` → Gear (Pets for `slot: pet`), `resource` → Materials, `quest` → Quest, everything else → Consumables (including station gear kept because it arrived out of order). Each tab is a slot array (`InventoryItem | null`) that grows to its capacity and never shrinks; items stack per `id + tier + upgradeLevel` within their tab. `addItems`/`removeItems`/`canFit`/`missingSlots`/`countItem` (`inventory.ts`) take the whole inventory and route each item to its tab, so a full tab only blocks or loses its own items. The inventory panel shows one tab at a time: a keyboard tablist (arrow keys, Home, End) whose buttons show used / capacity ("Materials 16/20", Quest only a count) and a red count on a full slot tab. Slot tabs show every slot, including empty and locked ones, padded to 40-slot pages. Pets and Quest list only the stacks they hold: Pets never fills, so its "owned / total" count reads as collection progress instead of a wall of empty slots.
- **Tab capacity** (`PlayerStore.inventoryCapacity()`, derived like `stats`): the `inventorySlots` stat keyed by tab. Gear, Consumables and Materials (`SLOT_TABS`) start at `statsInitialState.inventorySlots` (20) each; a modifier without a `tab` adds to all three (the Guild Satchel, +2), one with `StatModifier.tab` to that tab only (`slotDeltas`; skill nodes set it through `SkillNode.tab`, see `skill-tree.md` → Inventory slots). Pets has one slot per pet item id and never fills; Quest is unlimited (capacity `Infinity`: the array grows as items arrive). `stats.inventorySlots` stays the amount every slot tab gets (tabbed modifiers are left out of it); the stats panel shows that.
- **Destroy** (inventory panel): hovering an item shows a destroy button on its slot (not for quest items); it removes the whole stack (`PlayerStore.destroyItem`: same id, tier and upgrade level; other stacks of the id stay). A confirmation dialog (`DestroyConfirmComponent`) opens when the stack's tier is at or above `SettingsStore.confirmDestroyFromTier` (Settings tab → Items; default Trash, so every tier asks); below it the item goes at once. Quest items (`ItemType.quest`) have no button and `destroyItem` refuses them. Equipped items aren't in the inventory. There is no amount picker: the whole stack goes.
- **Slots past capacity are locked**: nothing is added there, but their items stay visible and can be used, sold or equipped. Only a migrated save (below) puts items there. `canChangeInventorySlots(deltas)` blocks anything that would shrink a tab below its used slots (skill refund and respec, equipping or unequipping gear with `inventorySlots`), per tab; `slotChangeBlockedTab(deltas)` returns that tab so messages can name it. Items already past capacity don't block: only items in the slots a shrink would lock count (`blockedTab(inventories, from, to)`), so a migrated tab over capacity never blocks changes to other tabs.
- **Save migration**: player save version 2. A version 1 save's flat inventory is split by `tabOf` in slot order (`splitInventory`); a tab with more items than its capacity keeps them all past capacity. No item is ever deleted. Used Guild Satchels (+5 slots each in version 1, the only permanent slot bonus) become +2 per slot tab.
- **Chests** (`ItemType.chest`: `rolls` picks from a weighted `loot` table of gold or item stacks) open on right-click: `PlayerStore.openChest` rolls the loot first (`rollChest`, `store/player/chest.ts`) and opens only when the rolled items fit, each in its tab (owner rule: only what was actually rolled needs room). When they don't, the chest stays, the roll is kept in `PlayerState.rolledChests` (per chest id, saved at once with `saveGameStateNow`) and reused on the next try, so retrying or reloading can't re-roll it (dropped in `removeItems` once the last chest of that id is sold or destroyed); the modal names the tabs and slots to free (`missingSlotsByTab`) without showing the loot. An opening is saved at once too. The contents, or "no room", show in a modal. Stackable, unsellable (open it instead). The Arena Chest is the first.
- **Spell scrolls** (`ItemType.spellScroll`) teach their `spellId` on right-click and are used up; a scroll for a spell already known can be sold. See `spells-and-buffs.md`.
- **Station upgrade items** never enter the inventory: `PlayerStore.addItems` installs them into `stations` instead (see `consumables-camp-crafting.md`).
- **Equipment panel** (`components/game/equipment/`): a five-row paper doll uses the same 64px shared slots and rarity shadows as the inventory. Head, chest, belt, legs and feet form the center column; the sides are symmetric: amulet and cape at the shoulders, weapon and gloves at the hands, ring and pet below. A decorative SVG body guide sits behind the grid. Empty slots show a marker and their type label; filled slots show the item art and upgrade level (name in the tooltip and aria-label). The heading counts equipped slots. Slot order in the DOM follows the grid row by row, so Tab moves left to right, top to bottom. The panel takes `$equipment-height` (26rem, in `game.component.sass`) of the right column; the scrollable quests panel below gets the rest, about 19rem instead of the old 25rem row. Stats and inventory keep their grid sizes. There is no footer hint; the tooltip says how to unequip. Slots are native buttons: hover or keyboard focus shows item details (including weapon element and granted spell), or an empty-slot hint to equip matching gear from inventory. Right-click, Enter, Space or screen-reader activation unequips (a `click` with `detail === 0`); a mouse left-click does nothing, matching the inventory; empty or blocked slots take no action and explain why. Tooltips prefer the left, append to the body and use automatic viewport placement; Escape or activation dismisses them. Inventory equip and swap rules are unchanged.
- **Equip**: right-click gear in the inventory, and right-click an equipment slot to unequip (left-click does nothing in either, so a stray click can't swap gear; consumables were already right-click). Clickable inventory slots wrap their art in a button: Enter, Space, screen-reader activation (`click` with `detail === 0`) or a touch tap runs the same equip/use action; shop and modal slots (`clickable=false`) render no button. The item leaves the inventory first, the old item goes back in; stats follow from `equipment`. A weapon's `damageType` is the element of auto-attacks and its `weaponCategory` (default melee) whether they are melee hits; an item's `spell` is known while it is equipped (`spells-and-buffs.md`). Item tooltips show the damage type and the spell, not the weapon category.
- **Drops** (`calculateEnemyDrops` in `player.store.ts`): each `EnemyDrop` is a 1-in-`chance` roll, amount in `minAmount..maxAmount`; drops with `requiredActiveQuestId` only roll while that quest is active. Shinies roll the normal table 10 times plus `shinyDrops` once.

## Upgrade level
- **Pathfinder's Seal** (`ItemID.pathfindersSeal`) is a rare Quest item from the Arena Chest's separate 1-in-10 bonus roll: unsellable (`value: -1`), indestructible, with the letter icon as placeholder art. `ChestItem.bonusRoll` names an item, a 1-in-N `chance` and its `registeredStat`; `openChest` guards the roll on possession and the saved permanent bonus. `rollChest` adds the eligible bonus outside its weighted picks, and the entire result uses the existing kept-roll rules. The chest tooltip explains its ordinary picks, separate Seal chance and the requirement that the actual rolled items fit.
- `PlayerStore.registerPathfindersSeal()` rechecks possession and non-registration, removes exactly one Seal and grants `permanentBonuses.upgradedDropChance` in **one state update**, then saves immediately. Base `upgradedDropChance` is 0; registration grants `PATHFINDERS_SEAL_UPGRADED_DROP_CHANCE` (10 percent) from `src/data/upgrade-data.ts`. A positive permanent bonus is also the saved registration marker; no second dialogue flag or save migration is needed. The stat is derived through the existing permanent bonus source and shown as a percentage in Progress.
- Shared online/offline `rollDropList` gives each equipment copy a separate `upgradedDropChance` percent roll to arrive at +1, splitting mixed results into their +0/+1 stacks. Unique equipment, pets and non-equipment never get this roll. Both regular and shiny drop lists use it; offline uses the simulation's seeded RNG. Shop purchases, crafting and chest/quest rewards are unchanged. This does not require The Cold Forge to be completed.
- Runtime inventory stacks and equipped items carry optional `upgradeLevel`; missing means +0. The stack key is `id + tier + upgradeLevel`, treating missing and explicit 0 alike. Adds, removes, capacity checks, destroy, sell, equipment swaps, chest contents, drop accumulation and offline receipts preserve it. Counts and removals without a rarity still span rarities, as before, but an omitted upgrade level selects +0.
- `src/data/upgrade-data.ts` holds the initial cap (+5), +10% per level, the extra +25% of base at the +5 milestone, cost factor `k = 1`, and the later success chances (+6: 90%, +7: 80%, +8: 70%, +9: 60%, +10: 50%). The Forge panel uses the merge store API and shared evaluator (see `towns-shops-guild.md`); Toric opens it after The Cold Forge. While it is open, inventory is locked to Gear and inventory/equipment activation selects a Forge input instead of equipping or unequipping. Native dragging and click/keyboard selection use the same automatic pair: a matching equipped base is preferred, with an inventory sacrifice.
- **Unique equipment** has `unique?: true` in item data and cannot be merged: quest-reward gear, shop gear with `maxStock: 1, refreshable: false`, and chest-only equipment (including Arena Chest pets). Pets cannot be merged regardless of the flag. `npm run validate` warns when quest-reward or chest-only equipment lacks `unique: true`; chest-only means no enemy drop, shop, crafting, quest reward, zone mastery or dialogue gift source.
- **Merge API**: `PlayerStore.mergeItem(base, sacrifice, rng = Math.random)` takes each source as `{ from: 'inventory', item: { id, tier, upgradeLevel? } }` or `{ from: 'equipped', slot }`. Inventory sources name a stack, not an amount; each consumes one owned copy. Missing upgrade level means +0. Equipped sources resolve the copy currently in that slot. Copies must have the same id, rarity and upgrade level, be non-unique equipment other than pets, and be below the cap. Two inventory sources require at least two copies; the same equipped slot cannot supply both.
- A merge attempt costs `value × 2 ** currentUpgradeLevel × UPGRADE_COST_FACTOR` gold. Unaffordable attempts are refused. On success, the base gains one upgrade level: an equipped base stays in its slot, an inventory base returns to its tab. The sacrifice is consumed; an equipped sacrifice empties its slot. Success is guaranteed through +5. The later-level failure path consumes only the sacrifice and gold, preserving the base unchanged. Stats remain derived from equipment.
- `evaluateMerge(context)` is a pure preview over inventory, equipment, capacity, gold and both sources, returning a ready plan (cost, chance and both resulting states) or a refusal. It uses the same `blockedTab`/`slotDeltas` checks as `canChangeInventorySlots`, including scaled gear slot bonuses and each tab's capacity. Both possible outcomes must fit before rolling (failure only when its chance is nonzero). This prevents lost upgraded stacks or a sacrificed slot bonus stranding items. Refusals spend nothing and never roll. The store applies inventory, equipment and gold together and returns `{ status: 'success' | 'failure', cost }` or `{ status: 'refused', reason }`; `inventoryFull` also includes `tab`. Other reasons are `missingCopy`, `mismatch`, `notEquipment`, `unique`, `pet`, `atCap`, `notEnoughGold`. Tests can inject RNG into the store or `rollMerge`, and preview later levels with `evaluateMerge(context, levelCap)` without changing the shipped cap.
- `upgradedStatAmount` in `stats.ts` scales each base gear stat by `1 + 0.1 * upgradeLevel`, adding 0.25 at +5 and above. Each scaled amount uses the existing six-decimal stat precision, retaining fractional stats; +0 leaves base amounts unchanged. `gearModifiers` supplies both derived stats and equipment capacity checks. Tooltip stats use the same calculation.
- Sell prices multiply the shop's existing rounded price by `2 ** upgradeLevel`; unsellable items stay unsellable.
- Inventory, equipment and shop slots show `+N` for upgraded items, with a diamond frame mark at +5. Tooltips and accessible names include the level. New labels use `items:upgradeLevel`, `items:upgradedName` and `items:upgradeMilestone`.
- Save version stays 2: no migration or rewrite is needed. Existing items without the field load as before; new levels persist with their stacks and equipment.
- Cheats: `dev.addItem(itemId, amount = 1, tier = defaultTier, upgradeLevel = 0)` (also `giveItem`) and `dev.equip(itemId, tier = defaultTier, upgradeLevel = 0)`.

## Intended behavior (owner decisions)
- **Enemy drops are lost when their inventory tab is full.** This is intended; other tabs are unaffected. Online, `processBattleEnd` returns the lost drops (`lostItems` in `inventory.ts`: what would not fit per id + tier + upgradeLevel; station upgrades never count) and `BattleManagerService.dropsLostToast` shows one toast per kill, a line per tab ("Materials full: Wolf Pelt lost"), in the battle view for 3 s. Offline counts them in `lostDrops` instead.
- **Unequipping, crafting and completing a quest must be blocked when the result has no inventory space**, and the UI must say why.
- **Spending gold must be blocked when the player can't afford it**, for every gold sink: dialogue fees, shops, respec/refund.
- **Never lower an `inventorySlots` source** (Guild Satchel, slot gear, skill nodes, base capacity in `statsInitialState`). A lower amount shrinks tabs in existing saves and can push them over capacity: items past capacity are kept, but the tab takes nothing new. If a source must drop, add a player-save migration that makes up the difference, for example by rescaling stored `permanentBonuses` (the version 1 → 2 Satchel rescale in `player.store.ts`).

## Invariants & gotchas
- **Stats are derived, not stored.** A new stat source must be added to the `stats` computed in `PlayerStore`, not applied with `updatePlayerStats`. Removing the source (unequip, expiry, refund) removes the stat; there is nothing to mirror.
- Derived stats are rounded to 6 decimals (no float drift). `mana` never shows above `maxMana`, and stored mana drops when `maxMana` does.
- **Inverted stats**: `attackSpeed` (seconds per attack), `manaRegenRate` (ms per mana) and `shopRefreshCooldown` (ms) are lowered by positive amounts (`INVERTED_STATS` in `stats.ts`). Data always uses "positive = better".
- The mana regen timer (`PlayerStore.manaRegenTimer`) is not a stat and is not saved.
- Stat units: multipliers are factors (`critMulti` 1.2 = ×1.2); `critChance` and `shinyChance` are percent; `damageVs*` are additive fractions (0.2 = +20%).
- Every `PlayerStat` needs an `app:playerStats.<stat>` label (`npm run validate` checks).
- **Gold per kill** is `ceil(Enemy.gold × goldCoinsMultiplier × 10 if shiny)` (`processBattleEnd`).
- **Item `value`** is the sell price (`sellItem`, any shop). `value <= 0` is unsellable: books, station gear, quest items and chests must stay there (recipes, spell scrolls and pets sell, so duplicates aren't dead slots; owner decision; town pets are the exception, `value: -1`, since each is given once), and a shop's price must be above the item's `value` (`npm run validate` checks both).
- `addItems` silently discards what doesn't fit. Callers that must not lose items check `canFit` first.

## How to extend
New equipment: the `add-equipment-item` skill. New stat: add it to `PlayerStat`, `statsInitialState`, the right display list, a row in `STAT_GROUPS` (`player-stats/stat-rows.ts`), `app:playerStats` and `app:statsPanel.descriptions`; if lower is better, add it to `INVERTED_STATS` in `stats.ts`; if it is earned and spent rather than granted, add it to `RESOURCE_STATS`.

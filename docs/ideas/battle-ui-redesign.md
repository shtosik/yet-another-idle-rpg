## Biggest problems

- Arena mechanics are only partly explained. The player sees targets, mounds, a shield label and time deductions, but lacks advance warnings, response deadlines and several consequence explanations.
- Mana and spell eligibility are separated. An apparently usable spell can silently do nothing; important active-effect information is absent or available only through icons/tooltips.
- Fixed shell columns, percentage battle rows, five fixed spell slots and absolute side controls leave little room for narrow screens or translated text.
- Progress controls and actionable states need explicit labels, keyboard operation and readable outcomes. Existing signals and most OnPush declarations provide a useful foundation.

### High

1. **Arcanist penalty is unexplained until time is already lost.** `src/app/components/game/battle/battle-nav-bar/battle-nav-bar.component.html:16`, `src/assets/locales/en/app.json:188`, `src/app/services/arena-bosses.service.ts:125`, `src/data/arena-data.ts:52`. The only visible penalty text is `-Ns`, rounded and shown only after a positive rounded total. Magic hits cost 0.2 seconds per damage, up to 5 seconds per hit and 60 seconds per fight; damage-over-time ticks count. Players can unintentionally accelerate a timeout without understanding why. Add a persistent Arcanist rule card before the first cast, a labelled penalty meter (`Time taken: X / 60s`) and a brief per-hit deduction notice. Explain that the toll uses magic hits, not the weapon's apparent theme; staff auto-attacks are not magic hits for this rule. Keep spells usable, with a clear cost warning.

2. **Burrower hides its deadline and failure consequence.** `src/app/components/game/battle/enemy/enemy.component.html:31`, `src/app/services/arena-bosses.service.ts:72`, `src/app/services/arena-bosses.service.ts:95`, `src/app/services/battle-manager.service.ts:73`, `src/data/arena-data.ts:54`. All hits stop while burrowed, yet damage-over-time ticks are spent. Show `Choose the shaking mound — 4s`, an expiring bar, the heal consequence, and `Burrowed: attacks cannot hit; damage-over-time ticks still expire`. Announce the correct mound through a non-motion, non-colour-only cue available to assistive technology. Show `Healed +N HP` on failure and a five-second +50% damage countdown on success. Current reduced-motion yellow ring is useful but still relies on colour/shape interpretation.

## Proposed normal battle layout

```text
+--------------------------------------------------+
| Zone name                         Mastery 1/3 [>] |
| Wave 8/10    Wave goal 6/10     Boss at wave 10    |
| [Previous wave] [Next wave: need 4 kills]          |
| Auto wave progression [Off]    Auto-eat [On]      |
+--------------------------------------------------+
| Enemy name                          [Shiny badge]|
| HP [=================--------]  1,250 / 2,000     |
| Weakness: [icon] Fire   (when node unlocked)       |
|                                                  |
|                  ENEMY SPRITE                    |
|             bounded hit feedback layer           |
|              or: Next enemy in ...               |
+--------------------------------------------------+
| Mana [=============----------] 18/30   +1 in 2s    |
| Buff: name 8s | Ambush: 1 hit | DoT: 3 hits left  |
| Food: effect 20s / ready 40s | Potion: ready 10s   |
```

Move wave arrows and automation out of the absolute sprite rail into the progress block. Move mana into the action area so spell decisions need no scan to another panel. Keep HP/name/weakness together above a stable sprite box. Move task details and mastery goals into expandable secondary sections, leaving claim status visible. Use opaque surfaces for header/status/action text and retain scene art primarily around the sprite. Buttons may wrap; do not shrink important labels to fit.

On phones, this same reading order becomes a single column. Use five equal spell columns only when targets and labels fit; otherwise wrap to three plus two, keeping slot order. Allow vertical scrolling instead of forcing percentage heights. On narrow desktop, budget against the actual battle panel width, not only the viewport. No player HP bar is proposed.

The mechanic card changes by champion; the shell and action area remain stable:

| Champion | Persistent explanation | Active state and outcome |
| --- | --- | --- |
| Brute, wave 5 | First weak point after 5s; strike for +50% damage for 10s | Next opening countdown; 3s target window; bonus countdown; missed-opportunity notice; next opening 30s after resolution |
| Arcanist, wave 10 | Magic-hit toll including damage-over-time; caps and staff distinction | Last deduction and labelled 60s per-fight meter; explicit cap-reached state |
| Burrower, wave 15 | First burrow after 20s; choose the shaking mound within 4s; wrong/late heals 10% max HP | Pick timer and accessible correct-mound cue; untargetable warning; heal feedback or +50% damage countdown for 5s; next burrow 20s after resolution |
| Yad, wave 20 | Shield every 5–10s after break; first matching-element hit damages and breaks it; another element next time | Named element plus icon, available matching attacks, blocked-hit feedback and shield-broken event; warn about spent empower charges |

Regular arena waves show a compact gauntlet rule rather than an empty mechanic card. Preserve wave/kills and the clock during respawns. Do not show zone tasks, wave arrows or Auto wave progression. ## Open questions for the owner

- Should champion rules be fully discoverable on first encounter, or should some remain learned through play? The proposal exposes timing, consequences and counters; it does not alter them.
- Should Yad's next shield use an exact countdown, or only the documented 5–10 second range? Should loadout preparation guidance appear before entry if the player lacks fire/air/water attacks?
- Does Leave need confirmation, or is consequence text and physical separation enough? It currently forfeits the attempt immediately, keeps earned XP/gold and shows no result modal.
- Should arena take priority over other panels while active on small screens, given the wall clock continues away from the Battle tab? What minimum phone width is supported?
- Should timeout show a full penalty breakdown and furthest champion for future planning? This requires a run summary beyond the current ArenaResult fields, not reconstructed estimates.
- Should normal progression remain an indefinite farming loop after a slow boss or show an advisory? There is no normal defeat condition; any time threshold or automatic retreat would be a separate behavior decision.
- Should mastery use a tap-open panel and should spell rearrangement have an explicit edit mode, to reduce accidental drags while casting? Confirm the desired touch interaction before implementation.
